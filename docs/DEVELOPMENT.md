# Development and dependency policy

Use this guide to prepare a contributor environment and run an interactive Jellyfin
sandbox. Run commands from the repository root. Tool versions are authoritative in
`.node-version`, `.python-version`, `global.json`, workspace manifests, and lockfiles.

## Prepare the toolchain

Install the exact pinned Python, Node.js, pnpm, and .NET SDK versions.
Docker is required for official-image reference extraction, sandbox, and package/browser
validation. Recreate the virtual environment after a Python upgrade.

```sh
python3.15 -m venv .venv
.venv/bin/python -m scripts.checks.check_pip && .venv/bin/python -m pip install --uploaded-prior-to=P1D -r requirements-check.txt
node scripts/checks/check-toolchain.mjs
pnpm install --frozen-lockfile
scripts/dev/bootstrap-references.sh
```

Bootstrap extracts compile references from the pinned official Jellyfin image without
starting a server. `JellyfinReferenceDir` overrides the reference location for both
builds and tests. `LYRICBRIDGE_PYTHON` and `LYRICBRIDGE_DOTNET` override local checker
executable locations. See [validation commands](CI.md#local-commands) for checks to run
after setup.

## Edit and check source

Edit `frontend/`, including static assets in `frontend/assets/` and the administrator
page in `frontend/admin/`. `dist/web/` is generated by `pnpm build`.
TypeScript 7 supplies `tsc` through `@typescript/native`; the `typescript` alias supplies
the TypeScript 6 JavaScript API used by ESLint and the source boundary checker.
Esbuild bundles the strictly checked application source.

`pnpm check` runs ESLint, Prettier, Knip, strict TypeScript, Ruff, Mypy, and .NET
whitespace formatting. `pnpm test:tooling` checks toolchain guards and dependency
policy. Generated and vendored sources are excluded. The demo HTML is excluded from
formatting because browser fixtures depend on exact inline-script hooks.

Use `pnpm format`, `pnpm format:python`, or `pnpm format:dotnet` to apply formatting.
Prettier uses 150 columns and four spaces, with two spaces for YAML.
Review [architecture boundaries](ARCHITECTURE.md) before moving ownership and
[feedback integration](FEEDBACK.md) before adding notices or confirmations.

## Test in a local Jellyfin sandbox

The helper installs into a pinned official Linux x64 container. After toolchain setup,
build the checkout and start the sandbox:

```sh
python3 -m scripts.dev.local_jellyfin rebuild
```

Open [local Jellyfin](http://localhost:18096/web/), finish setup, and add `/media` as a
music library. Copy sample songs and sidecar lyrics into `.build/local-jellyfin/media/`,
which is mounted read-only. Configuration, credentials, and plugin data stay under
ignored `.build/local-jellyfin/`. Use test accounts and leave credentialed providers
unconfigured unless you intend external calls.

After source edits, run `rebuild` again and reload your browser. It builds before
stopping the old sandbox, replaces only its LyricBridge package, and preserves server
configuration/data. Use a separate browser profile for playback/layout tests.
`start` installs the existing matching `dist/lyricbridge-VERSION.zip` without rebuilding;
if missing or mismatched, use `rebuild`.

For media symlinks outside the sample directory, mount each target at its original
absolute host path. For example, if a sample symlink targets `/srv/test-music/album`:

```sh
python3 -m scripts.dev.local_jellyfin start --media-mount /srv/test-music/album
```

Replace that example path with an existing directory accessible to Docker, including
any FUSE permissions. Each mount is read-only. Repeat `--media-mount` for more targets.
Mounts persist across stops/rebuilds; a new list replaces them and
`--clear-media-mounts` clears them.

Inspect or stop the owned container with:

```sh
python3 -m scripts.dev.local_jellyfin status
python3 -m scripts.dev.local_jellyfin logs
python3 -m scripts.dev.local_jellyfin stop
```

`stop` retains test data and leaves other containers alone. `start --port 18097`
uses another localhost-only port; repeat that port on subsequent rebuilds.
For a fresh sandbox, stop it, remove only `.build/local-jellyfin/`, then start/rebuild.
This deletes test accounts, credentials, plugin data, and sample media.
The helper's storage locations are fixed; never substitute production storage.

Check web injection under **Dashboard → Plugins → LyricBridge → General**.
Native clients and independently hosted Web need separate integration checks.
Automated [package installation checks](CI.md#local-commands) own another temporary
server and delete it afterward. This sandbox does not verify ARM64 or physical-device
performance.

## Upgrade dependencies

Renovate, pnpm, and pip enforce a 24-hour minimum release age; Renovate adds a
30-minute companion-package buffer. pnpm enforces 1440 minutes with narrow reviewed
exact-version exceptions. pip uses `--uploaded-prior-to=P1D`;
`scripts/checks/check_pip.py` verifies support, and missing upload-time metadata fails
installation. NuGet uses locked restoration and Renovate's age policy.

Only esbuild may run dependency lifecycle scripts. Restore explicitly with frozen
lockfiles; checks must not install implicitly. Keep Playwright's package, lockfile,
and digest-pinned image together. Review intentional visual changes before updating
screenshot baselines or tolerances.

GitHub Actions are SHA-pinned. `renovate.json` permits checked routine updates to
automerge. Compilers, interpreters, package managers, runner OS, pre-1.0 esbuild minors,
and provider/converter minors require review. Playwright package/image patches are
grouped; browser minor/major upgrades require review. Backend test infrastructure and
artifact actions have separate groups.

Enable repository auto-merge and require aggregate `validate` plus up-to-date branches
on `main`; avoid requiring conditional jobs individually. Bot bypasses must not skip
validation. If bot workflows stop after a platform update, check event permissions and
pinned action interfaces before changing policy.
